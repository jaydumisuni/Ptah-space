# E07 E01 deployment-owned Node client candidate

**Engineering candidate only. It has no embedded CA, Node identity, secret,
placement admission, E02 dispatch executor, or installation side effect.**

`services/ptah-node/src/bin/ptah-e01-node-client.rs` is a bounded E01
mutual-TLS session client for Ptah's existing read-only enrollment
gateway. It requires all of these deployment-owned inputs:

- Control gateway socket, exact TLS server identity and approved client
  cert/key/control CA files (private key mode 0600 on Linux).
- An **already A03-retained**, canonical NodeRestartSeed JSON file
  (private mode 0600). It does **not** call `NodeAgent::bootstrap`
  in normal execution or mint NodeId.
- The exact canonical approved `core.node_enrollment` EntityRef as
  JSON, matching Control's installed enrollment projection.
- A bounded 2–3600-second explicit session duration.

Before opening a network socket, the client checks TLS configuration,
locks the seed state, advances Generation+ConnectionEpoch using
`NodeAgent::restart`, atomically replaces the seed and fsyncs both file
and parent directory. Another process cannot consume the same state
under the held OS lock. E01 Hello/Ack must match exact Node state;
TLS v1.3 is mandatory; bounded sequential Heartbeats and Close are
the only emitted post-handshake messages.

**Current bounds:** Linux E01 candidate only. Native Windows refuses
to run until audited ACLs and durable Node state custody exist.
The listener in Ptah Control still binds **loopback only**, requires
deployment-owned certificates and an approved enrollment projection,
and **rejects E02 dispatch frames**. Do not proxy it publicly or
interpret its E01 session as production execution authority.

Example, **only after an approved deployment provides real values**:

```sh
ptah-e01-node-client \
  --endpoint 127.0.0.1:9238 --server-name control.example.internal \
  --client-cert /run/ptah/node/client.pem \
  --client-key /run/ptah/node/private.key \
  --control-ca /run/ptah/node/control-ca.pem \
  --node-seed /var/lib/ptah/node/restart-seed.json \
  --enrollment-ref-json '{"entity_kind":"core.node_enrollment","entity_id":"<approved-id>"}' \
  --seconds 30
```

Values above are placeholders, **not usable admission credentials**.
Never commit real certs, keys, enrollment projections or Node seeds.

## Evidence and no-go boundaries

A physical KRATOS black-box test also executes the compiled E01 client,
converts Ptah's **existing test-only** DER certificates into ephemeral PEM
files using OpenSSL, runs the actual Control retained-session handler over
loopback TLS 1.3, checks authenticated Hello/Ack and sequenced Heartbeats,
and verifies clean Close and persisted Node Generation/Epoch advancement.
That test does not provision real certificates or write outside isolated
test-state storage.

CI and KRATOS tests exercise missing configuration, insecure/symlink
state rejection, restart Generation/Epoch monotonicity and two separate
black-box binary regressions proving missing production credentials
leave the persisted Node seed byte-for-byte unchanged. E01 TLS
fixture tests run independently. Passing these tests means the client
mechanism is ready for review; it does **not** mean actual KRATOS or
ATHENA has an approved host role, a live Control-issued production E02
Reservation/Lease/Fence, a deployed E02 listener, or Creative Studio
service admission.

Issue #114 remains open until actual production identities, two
current approved E05 platform profiles, signed live session receipts
and independent deployment/revocation review are present. E07 #110,
D04 #115 and physical acceptance #116 remain separate. Current
Phase-0C pinned Ubuntu image drift is not automatically equivalent
to an E05 runtime policy violation; resolve both authorities explicitly.

The new client must be reviewed through Patrol and Sergeant before
deployment. Nothing is installed or started by this change.

### Disposable Windows DPAPI + DACL qualification (ATHENA, 2026-10-15)

ATHENA successfully ran `tools/e07/windows-node-custody-selftest.ps1`
under Windows PowerShell 5.1 against an isolated per-user temporary
directory. The script creates random **disposable** Node-like state in
memory, encrypts it using DPAPI CurrentUser, writes it to a protected
directory with an inheritance-disabled DACL limited to the Windows user,
SYSTEM and Administrators, and verifies decryption and tamper rejection.
The original .NET method mismatch (`RandomNumberGenerator.Fill`) was
repaired to use the compatible `RNGCryptoServiceProvider.GetBytes`.

Result: `ptah.e07.windows-custody-disposable-selftest.v1` / PASS;
DPAPI round-trip, restricted ACL, and tamper rejection all PASS.
The test does not mint a Ptah Node enrollment, write production secrets,
store a private key, qualify crash-atomic Node generation updates, or
activate E01 TLS. The actual Windows E01 binary **continues to reject**
unprovisioned startup pending full state-custody review. The Windows
hosted E07 qualification job now runs the same disposable self-test.

Production E01 enrollment still needs a reviewed native Windows state
update path, ownership and revocation, and an approved certificate and
Node identity. This result alone must never mark E07 accepted.


### ATHENA interrupted-state and exclusive-lock qualification (2026-10-15)

A second disposable Windows PowerShell 5.1 test on ATHENA passed after
correcting .NET Framework \`File.Replace\` to supply an explicit backup path.
The test now verifies that abandoning a staged, encrypted generation does
not modify the canonical state; that a \`File.Replace\` commit yields the new

that protected ACLs survive replacement; and that a second process cannot
acquire the exclusive restart file handle. The original DPAPI round trip,
tamper rejection, and ACL tests also pass.

Result schema: \`ptah.e07.windows-custody-disposable-selftest.v1\`;
