# Security Policy

## Reporting a vulnerability

Report security issues privately by email to:

```text
support@thetechguyds.com
```

Use the subject prefix:

```text
[PTAH SECURITY]
```

Do not open a public issue when a report includes exploit details, credentials, private endpoints, personal data, or information that could put users or systems at risk.

## What to include

Provide only the information needed to assess the report:

- affected version, commit, or path;
- clear impact;
- minimal reproduction steps;
- expected and observed behaviour;
- relevant logs with secrets and personal data removed;
- a proposed mitigation when known.

Do not send credentials, private keys, customer records, device identifiers, production configuration, or large confidential evidence bundles unless a maintainer provides an approved secure transfer route.

## Supported versions

Ptah is currently in pre-release development. No production release is supported yet. Supported versions and security-update commitments will be listed here when public releases begin.

## Coordinated disclosure

Please allow maintainers time to validate and correct a report before public disclosure. Disclosure timing should be coordinated when early publication could expose users or unresolved systems to harm.

This policy does not promise a bounty, response deadline, or production support service.
